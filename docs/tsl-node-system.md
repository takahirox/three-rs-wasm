# TSL node system port

`webgpu_tsl_editor` runs any TSL the user writes and shows the WGSL or GLSL that
three.js r186 generates for it. Reproducing it means porting three's node
system: `src/nodes` (218 files), the WebGPU and WebGL fallback node builders,
`renderers/common/nodes`, `materials/nodes`, and the renderer paths that
`renderer.debug.getShaderAsync` takes. The port lives in the `three-tsl` crate
(`tsl/`). It is accepted only when every corpus program matches its golden
character for character. A subset is not acceptable.

## Design

The JavaScript is dynamic, and its output depends on that dynamism:

- a node's children are its own properties in creation order;
- `generate.length` selects how a node is built;
- uniforms are sorted by node id, so module evaluation order matters;
- user TSL receives nodes as chainable Proxies, and V8's TypeError texts reach
  the editor.

`tsl/src/rt` is therefore a JavaScript object model in Rust:

- `Val` values, and objects with prototype chains;
- data and accessor properties, in JavaScript's key order;
- functions with arity, classes as constructor + prototype;
- `Map`, `Set` and `WeakMap`;
- the built-in methods the sources use, and V8's error messages.

Every three.js class is ported method for method on this model. The Rust file
of each JS file has the same relative path, in snake case. Module-level code
runs in the ES module evaluation order of `Three.WebGPU.js`, which is
`.cache/tslsrc/module_order.txt` and is regenerated by
`tools/tsl/module_order.py`. Node ids, and the counters of materials,
textures, objects and geometries, therefore advance as in the original.

User code stays JavaScript and runs as the editor runs it (an `AsyncFunction`
with `THREE`). `rt::interop` hands Rust objects to it as Proxies over handles,
and hands its values to Rust as `Val::Js`. Both sides keep their identities.
`three/tsl` is a generated module whose exports are the Rust TSL functions.

## Verification

- `tests/tsl/corpus.json`: 4,148 programs in 104 chunks. Each chunk is one
  editor session.
- `tests/tsl/golden.json.gz`: r186's output for every program, recorded by
  `node tools/tsl/golden.mjs` from `reference/three-js/tsl-corpus.html`. For
  each program it holds:
  - WGSL with sRGB output, GLSL ES 3.0, and WGSL with linear output;
  - the thrown message;
  - the console.
- `tools/tsl/check.mjs` replays the corpus against the port in Node.js and
  reports the mismatches.
